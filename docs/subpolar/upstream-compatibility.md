## Client and provider compatibility

The Subpolar integration commits after merge `923e478` do not modify `apps/web`, `apps/desktop`, `apps/mobile`, or `packages/contracts`. They add no client RPC methods or event schemas. T3 remains the owner of the client protocol and orchestration. The Subpolar ACP bridge is configured as an existing local ACP executable; no new provider kind is registered. T3's native Pi provider remains separate and available.

This source-level compatibility check does not prove the clients work against an integrated Subpolar runtime. A package-level mock Pi test exercises two completed ACP turns through the Subpolar runtime host, including history passed into the second Pi run; it has not run locally because the incomplete dependency install left `effect` and `@effect/vitest` unavailable. A new composite test in `apps/server/src/orchestration-v2/Adapters/AcpAdapterV2.test.ts` connects T3's generic ACP adapter to the managed ACP proxy and a fake environment manager/worker. Its mock Pi executor completes a turn, requests a tool permission that T3 accepts, and reports the managed worktree cwd; the test also checks worker termination. The focused composite test passed (1 passed, 118 skipped). It does not exercise a real Pi runtime or Docker-backed environment. Setup scripts route through managed terminals only for allowlisted Subpolar provider instances; the focused server tests could not collect because Vite+ native dependencies and workspace links are unavailable. Preview discovery and browser proxying remain deferred: the existing subscription is environment-wide and carries no trusted thread/worktree context, while the manager's byte tunnel does not provide a browser HTTP/WebSocket route. Per the integration plan, no new client RPC or event contract was added. No full event-source/client ACP flow or authorized live Pi turn has been verified. ACP configuration remains server-side and operator supplied.

T3's Vitest-based provider/session tests and typechecks remain unverified because the local dependency install did not complete. The composite managed mock test passed; it uses a fake manager/worker and mock Pi, so it does not establish a real Docker or Pi turn. There is no verified full event-source/client ACP flow or authorized live Pi turn. Earlier successful image builds are historical; current image build is in progress, and gateway startup/persistence remain unverified.

The authenticated Docker manager and `subpolar` admin CLI, approved ACP argv execution, managed ACP-to-worker stdio proxy, explicitly allowlisted T3 terminal and setup-script routing, image-based Dev Container discovery, constrained Dockerfile builds, locked and allowlisted Features, literal `containerEnv`, lifecycle hooks, and constrained optional Compose support exist in source. Compose Dev Container support is off by default and requires `SUBPOLAR_ENABLE_DEVCONTAINER_COMPOSE=true`; its internal network can still reach host services, so enabling it is an administrator trust decision. Per-environment lifecycle calls and registration reconciliation are serialized within one manager process. The manager still does not enumerate Docker-wide orphans, recover in-memory terminal handles after process restart, or coordinate across manager processes. Pi agent configuration and native sessions live in a manager-owned volume; resume validates the saved Pi session ID and cwd. T3 remains authoritative for thread history, and the runtime does not persist run outcomes or replay events. An opt-in, session-bound ACP credential bridge uses the configured T3 provider instance and a server-side provider allowlist. Its same-process write lock cannot coordinate separate T3 server processes. The opt-in model egress extension routes bounded HTTPS through the T3 host, is bound to the active ACP session and configured Pi provider ID, pins a public IPv4 address for fixed provider API hosts, rejects redirects, and leaves the worker on Docker's `none` network. It supports only provider HTTP adapters honoring Pi's fetch override; WebSocket transports, Google Vertex, custom endpoints, model catalog refresh, deferred operations, and a live Pi turn remain unverified. Preview discovery remains unavailable until trusted per-thread/worktree routing can be added without violating the plan's no-new-client-contract requirement. The manager's local registration file is not a distributed coordination mechanism.

The code and focused package checks establish an upstream-compatible integration seam, not completion of the integration acceptance criteria. Docker-backed checks still do not establish a full T3 event-source/client turn, real Pi provider turn, production gateway startup/state recovery, PTY attach, or Docker-backed Dev Container feature matrix. See [the architecture](architecture.md) and [migration matrix](migration-matrix.md) for ownership boundaries and retained/deferred source functionality.
